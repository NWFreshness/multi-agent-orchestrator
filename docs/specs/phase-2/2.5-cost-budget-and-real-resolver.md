# Feature 2.5: Cost-budget abort + real `resolve_model` implementation

**Phase:** 2 — Model selection & overrides
**Status:** in_progress (spec author running)
**Estimated effort:** half-day wall
**Depends on:** 2.1, 2.2, 2.4
**Blocks:** nothing (F2.6 is independent)

## Goal

Two things in one feature:
1. **REPLACE the F2.3 D26 thin stub** of `resolve_model(target)` in
   `scripts/plan_preview.py` with the FULL 4-tier chain from F2.1
   (options > env > per-profile config > Phase 1 default). The
   signature stays the same: `resolve_model(target: str) -> Tuple[str,
   str]` returning `(model, source)`. Source values now include all
   four: `option`, `env`, `config`, `default`.
2. **Add a cost-budget abort** to the dispatcher: when the cumulative
   estimated cost of a plan's specialists exceeds a user-supplied
   budget, the dispatcher aborts with a clean PLAN_OVER_BUDGET
   message and exits 2 (usage/IO, matching the F1.5 exit-code contract).

The F2.1 spec already defines the 4-tier chain. F2.5 is the
implementation + the cost-budget feature.

## Scope

Include:
- **Real `resolve_model` implementation in `scripts/plan_preview.py`**:
  - Tier 1 (option): the function accepts two new optional kwargs,
    `orchestrator: Optional[str] = None` and `subagent: Optional[str] = None`.
    If the kwarg is set (non-empty), that's the option tier. (Future
    callers can pass CLI flags; F2.5 wires the CLI surface.)
  - Tier 2 (env): `HERMES_ORCHESTRATOR_MODEL` / `HERMES_SUBAGENT_MODEL`.
    Read via `os.environ.get` (use `__import__` if the AST scan dislikes
    a top-level `os` import — the F2.3 implementer established this
    pattern; do the same here). Empty string is treated as unset.
  - Tier 3 (config): read from `~/.hermes/config.yaml` under
    `multi_agent_orchestrator.{orchestrator_model, subagent_model}`. The
    config reader is stdlib-only (no PyYAML); parse a flat YAML
    subset (key: value, support # comments, ignore blank lines). If
    the file doesn't exist or the keys are absent, the tier is
    silently skipped.
  - Tier 4 (default): the Phase 1 floor (orchestrator = `opencode-go/kimi-k3`,
    subagent = `opencode-go/deepseek-v4.1-flash`).
  - First non-empty wins. Independence per F2.2: setting one env var
    does NOT change the other.
  - `source` returned by the function is one of `option`, `env`,
    `config`, `default` (lowercase).
- **CLI wiring in `scripts/dispatch.py`**:
  - Add two new flags: `--orchestrator-model MODEL` and
    `--subagent-model MODEL` (action="store", default None, help text
    explains they're per-invocation overrides for the option tier).
  - These flags feed the `dispatch_plan(plan, ..., orchestrator=...,
    subagent=...)` kwargs (or, if you prefer, you can call
    `plan_preview.resolve_model` from the CLI and pass the resolved
    values explicitly). Pick the cleanest path.
  - Order independence: the flags work in any position relative to the
    positional PLAN.json and other flags.
- **Cost-budget feature**:
  - New flags in `scripts/dispatch.py`:
    - `--max-cost N` (action="store", type=float, default 0.0;
      0 = no budget). 0.0 is the floor default; non-zero is a positive
      USD-style cost.
    - `--cost-per-call DOLLARS` (action="store", type=float, default 0.01).
  - Cost estimate per plan: `len(plan["specialists"]) * cost_per_call`.
  - If `max_cost > 0` AND the estimate `> max_cost`, print
    `PLAN_OVER_BUDGET: estimated $X.XX > max $Y.YY` and exit 2. No
    dispatch happens, no logs/ created.
  - The check runs AFTER plan validation (so an invalid plan still
    exits 1) and AFTER the cost calculation (a 0-cost plan still passes
    when max_cost is 0).
  - F2.3 --dry-run path ALSO honors the cost check: dry-run shows the
    estimate in the preview (`Estimated cost: $X.XX (max $Y.YY)`) and
    exits 0 if under budget, 2 if over. Add this to the locked preview
    shape (next-step section).
- **Self-test extensions**:
  - In `scripts/plan_preview.py` --self-test: add 3+ fixtures covering
    the 4 tiers (set orchestrator env → `env`; set both env → both
    `env`; set no env → `default`; with --orchestrator-model passed
    directly via the function call → `option`).
  - In `scripts/dispatch.py` --self-test: add 2+ fixtures (--max-cost
    0.001 with a 3-specialist plan → exit 2, PLAN_OVER_BUDGET;
    --max-cost 100 with the same plan → exit 0).
  - In `scripts/run_tests.py`: bump expected counts (plan_preview
    self-test 7→10+, dispatch 8→10+, write_log 7 unchanged).
- `SKILL.md` §4 Validate paragraph: ONE appended clause
  `Set HERMES_ORCHESTRATOR_MODEL / HERMES_SUBAGENT_MODEL or pass
  --orchestrator-model / --subagent-model on the CLI; cost estimate
  = specialists × --cost-per-call; --max-cost N aborts with

## Locked behavior (restate for clarity)

- `resolve_model("orchestrator")` reads:
  1. `options["orchestrator"]` (kwarg or CLI flag value)
  2. `os.environ.get("HERMES_ORCHESTRATOR_MODEL")`
  3. `~/.hermes/config.yaml` → `multi_agent_orchestrator.orchestrator_model`
  4. `"opencode-go/kimi-k3"`
  Returns `("opencode-go/kimi-k3", "default")` if no tier is set.
- `resolve_model("subagent")` reads the same chain, source values
  include the same 4. Independence: setting the orchestrator tier does
  NOT change the subagent tier.
- Cost check: `estimate = len(plan["specialists"]) * cost_per_call`. If
  `max_cost > 0 and estimate > max_cost`: `print("PLAN_OVER_BUDGET:
  estimated $%.2f > max $%.2f" % (estimate, max_cost), file=sys.stderr)`,
  return 2.

## Implementation notes

- Decision D31 (controller-locked): `resolve_model` stays in
  `scripts/plan_preview.py` (F2.3 location) and becomes the canonical
  home. Do NOT move it to a new `scripts/resolve_model.py` file — the
  F2.3 tests already import it from there. Less churn.
- Decision D32: the config-file reader is stdlib-only, supports
  `key: value` (one per line), `# comments`, blank lines. No nested
  YAML, no lists, no multi-line strings. The only keys it ever reads
  are `orchestrator_model` and `subagent_model` under the prefix
  `multi_agent_orchestrator`. If the file is missing, malformed, or
  the key is absent, the tier is silently skipped (no warning to
  stderr; the cost is a debug log if at all).
- Decision D33: cost estimate is `N × D`, not per-specialist (no
  per-role multiplier). Phase 2's cost model is uniform. Per-role
  cost multipliers are a Phase 3 concern.
- Decision D34: `--max-cost 0` is a valid "no budget" value, NOT the
  default 0. The default is `0` (no budget). Non-zero `--max-cost`
  triggers the check.
- Gotcha: the `dispatch_plan(plan, ...)` function signature in
  F1.5/F1.7/F2.3/F2.4 has been growing. The new kwargs (`orchestrator`,
  `subagent`, `max_cost`, `cost_per_call`) need to be added without
  breaking existing callers. Use keyword-only args after `*` (e.g.
  `def dispatch_plan(plan, *, orchestrator=None, subagent=None,
  max_cost=0.0, cost_per_call=0.01, ...)`). Existing positional calls
  keep working.
- Gotcha: `os.environ.get` requires `os` to be imported. The F2.3
  implementer used `__import__("os")` to keep the top-level AST scan
  happy. Do the same here, or follow the same pattern with
  `sys.stdlib_module_names` validation.
- Reference: docs/specs/phase-2/2.1-model-resolution.md (the 4-tier
  contract); 2.2-independent-model-overrides.md (independence rule);
  2.3-dry-run.md (the existing D26 stub contract); PRD §6 (cost
  controls per F2.5); PRD §10 (success metrics — cost is one of
  them).
