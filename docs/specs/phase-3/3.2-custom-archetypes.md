# Feature 3.2: Custom archetypes via `~/.hermes/agents/*.yaml`

**Phase:** 3 — Advanced
**Status:** completed
**Estimated effort:** half-day wall
**Depends on:** nothing (independent surface; builds in listed order after 3.1)
**Blocks:** nothing

## Goal

The skill discovers user-defined specialist archetypes from
`~/.hermes/agents/*.yaml` and offers them alongside the F1.3 static
catalog: a stdlib-only `scripts/discover_archetypes.py` lists and
validates custom archetype files, and a contract doc defines the YAML
shape. No validator changes — F1.4 E4 already permits unknown roles
(warning, not error), so custom roles dispatch today.

## Scope

Include:
- **`references/custom-archetypes.md`** (new): contract doc. Defines:
  - Location: `~/.hermes/agents/*.yaml` (D41). Missing dir = zero
    custom archetypes (not an error).
  - File shape, flat-YAML-subset only, one archetype per file (D42):
    ```yaml
    name: arxiv-fetcher
    purpose: Pulls papers and metadata from arXiv.
    tools: web_search, web_extract, file
    model: opencode-go/deepseek-v4.1-flash
    ```
    Required: `name`, `purpose`. Optional: `tools` (comma-separated,
    default `file`), `model` (default = Phase 2 resolved subagent
    model). `#` comments + blank lines allowed; anything else
    (nesting, lists, multi-doc) silently ignored per the F2.5
    flat-subset precedent.
  - Naming: filename stem SHOULD match `name` (warning if not; `name`
    field wins).
  - Malformed files (missing name/purpose) are SKIPPED with a
    `WARNING:` line, never fatal (D43).
  - Name clash with the F1.3 static catalog: custom definition wins
    (orchestrator-side rule, stated not enforced — the static catalog
    is markdown, not machine-readable).
- **`scripts/discover_archetypes.py`** (new, stdlib-only: `argparse`,
  `json`, `os`, `pathlib`, `sys`, `typing`):
  - Dir resolution: `--agents-dir PATH` > `HERMES_AGENTS_DIR` env >
    `~/.hermes/agents` default (D41). Empty string env = unset.
  - Output: one `name | purpose | tools | model | source-file` line per
    valid archetype (sorted by name), plus `N custom archetype(s)`
    summary to stdout. Warnings to stderr. Exit 0 always on success
    path (even zero archetypes — prints `no custom archetypes`).
    Exit 2 on usage/IO (unreadable dir that EXISTS, i.e. permission).
  - `--self-test`: 5 fixtures in a temp dir under `/tmp`
    (`_f32_agents_<pid>`, created + removed by the test; `tempfile`
    is NOT in the locked import set so use `os`/`pathlib` directly):
    1. valid file → listed with tools split + model passthrough;
    2. missing `purpose` → skipped with WARNING, valid sibling still listed;
    3. missing dir → exit 0 + `no custom archetypes`;
    4. `--agents-dir` override respected over default;
    5. absent `tools`/`model` → defaults (`file` / empty = resolved default).
    Prints `SELF_TEST: 5/5 passed` in the exact `<N>/<N> passed` form
    the driver greps for.
- **`scripts/run_tests.py`**: add `("discover_archetypes.py", 5)` to
  SUITES (appended last — D19 order lock: existing three stay first).
  EXPECTED_TOTAL becomes 44 via the existing `sum()`.

## Locked behavior

- Decision D41 (controller-locked): dir resolution
  `--agents-dir` > `HERMES_AGENTS_DIR` > `~/.hermes/agents`. Mirrors
  the F2.1 option > env > default chain shape (no config tier — user
  files ARE the config).
- Decision D42: flat `key: value` subset only (F2.5 precedent);
  `tools` is comma-separated on one line. Rationale: stdlib-only,
  no PyYAML, matches the locked import set.
- Decision D43: malformed → skip + `WARNING:` to stderr, exit stays 0
  (one bad file must not blind the orchestrator to the good ones).
  Missing dir → exit 0 with `no custom archetypes` (the common
  first-run state — `~/.hermes/agents` does not exist today).
- Decision D44: validator untouched. Custom roles already dispatch
  (E4 warning path); F3.2 adds discovery, not permission.
- Gotcha: `pathlib.Path.home()` resolves `~` — do NOT shell-expand;
  keep it stdlib-`pathlib`.
- Gotcha: self-test must NOT touch the real `~/.hermes/agents`
  (it doesn't exist and must not be created). All fixtures live in
  the temp dir, always passed via `--agents-dir` or env override...
  env override in-test means mutating `os.environ` — save/restore in
  `finally`. Simpler: fixtures 1–3,5 use `--agents-dir` argv form
  via `main([...])`; fixture 4 sets env with save/restore.
- Gotcha: the driver's `<N>/<N> passed` grep — self-test must print
  exactly `SELF_TEST: 5/5 passed` (match existing per-script idiom).
- Reference: PRD R17; F2.5 `_config_value` flat-subset pattern;
  run_tests.py SUITES + D19 order lock.
