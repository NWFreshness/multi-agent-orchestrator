# Feature 3.5: Async background run mode

**Phase:** 3 — Advanced (last feature)
**Status:** completed
**Estimated effort:** half-day wall
**Depends on:** nothing (independent surface; builds in listed order after 3.4)
**Blocks:** nothing

## Goal

Long dispatches run detached: `scripts/dispatch.py PLAN.json
--background` re-execs itself detached (new session, stdio to a log
file), prints a one-line handle (`background: pid=<n> log=<path>`),
and exits 0 immediately. The user polls with `tail -f` on the F3.4
progress sink (or the trace) and owns the process with normal shell
tools. No status/kill API in the skill — the shell owns the process.

## Scope

Include:
- **`scripts/dispatch.py`**:
  - Flag `--background` (store_true, default False, order-independent).
  - In `main()`, AFTER validation + cost-budget check + dry-run
    handling, BEFORE dispatch: if set, call internal
    `_spawn_background(argv)` and exit 0. Placement rationale: an
    invalid/over-budget plan must fail in the FOREGROUND (fast,
    visible errors) — only a dispatchable plan detaches.
  - `_spawn_background(argv) -> int`: rebuilds child argv as
    `[sys.executable, <abspath dispatch.py>, <plan>] + forwarded flags`
    (everything except the `--background` token itself; `--self-test`
    never reaches here — see D54). Launches via
    `subprocess.Popen(..., start_new_session=True, stdout=log_f,
    stderr=subprocess.STDOUT)` with
    `log_f = open(logs/background-<UTC-ts>.log, 'wb')` (parent dirs
    created). Prints
    `background: pid=<n> log=<log path> trace=<trace path>` to stdout
    and returns 0. Parent closes its handle immediately (child holds
    its own fd — no hang on parent exit).
  - D54: `--background --dry-run` → `error:` + exit 2 (backgrounding
    a no-dispatch preview is meaningless). `--background --self-test`
    → exit 2 likewise (self-test branch runs first; reject the combo
    explicitly rather than silently ignoring the flag).
  - POSIX-only detach (`start_new_session`); help text says so. No
    Windows `creationflags` branch in F3.5 (repo runs macOS; YAGNI).
  - `--self-test` +2 fixtures (19→21): BG (build tiny plan, call
    `_spawn_background` with `--progress` sinkdirectly, poll the sink
    for the record count with a 30s `datetime` deadline, then
    `os.waitpid` the child and assert its exit 0 + sink lines parse)
    and BG_EXCLUSIVE (`main([plan, --background, --dry-run])` → 2;
    `main([--self-test, --background])` → 2). Reap every spawned
    child in-test (`os.waitpid`, `os` is in the locked set) — no
    zombies, no leaked children.
- **`references/background.md`** (new, short): handle-line contract,
  log path, polling recipe (`tail -f` progress sink → trace →
  `write_log.py`), ownership rule (D55: `kill <pid>` stops it; no
  skill-side status/kill), `--background` + `--progress` pairing
  recommendation, POSIX note.
- **`scripts/run_tests.py`**: dispatch 19→21. EXPECTED_TOTAL 53→55
  via existing `sum()`.
- `SKILL.md` §8: ONE appended bullet for `references/background.md`.
- `README.md` status table only: F3.4 → Done, add F3.5 In progress.

## Locked behavior

- Decision D53 (controller-locked): detach = re-exec self with
  `start_new_session=True`, stdio redirected to
  `logs/background-<UTC-ts>.log`, parent prints the handle line and
  exits 0. Rationale: re-exec keeps ONE dispatch code path (the child
  is a normal foreground dispatch) — no forked logic to drift.
- Decision D54: `--background` is mutually exclusive with `--dry-run`
  and `--self-test` (exit 2 + `error:`). Silent flag-ignoring is
  banned: a user who asks for background + dry-run has a wrong mental
  model and must hear about it.
- Decision D55: process ownership lives in the shell. Skill offers no
  status/kill surface; the F3.4 progress sink is the observability
  surface (`tail -f <sink>`), the trace is the completion surface.
- Gotcha: strip ONLY the exact `--background` token when rebuilding
  child argv (a `--progress` path value that happens to equal the
  string is positional-guaranteed distinct — rebuild by filtering the
  flag token, not by value matching; simplest correct: iterate argv,
  drop the first exact `--background` match... but a user could pass
  it twice (harmless dup) — drop ALL exact matches, keep everything
  else byte-identical including order.
- Gotcha: the child's cwd must equal the parent's (relative
  `logs/` + `.cache/` resolve identically) — `Popen(cwd=os.getcwd())`
  explicitly (`os` is locked-set; never inherit implicitly).
- Gotcha: BG fixture deadline uses `datetime` (locked set), NOT
  `time.sleep` loops without bound — poll every 0.2s up to 30s, then
  `kill` + `waitpid` + FAIL (a hung child must never escape the
  self-test).
- Gotcha: `--self-test` inside a background child would recurse
  spawning — D54's exclusivity plus stripping makes this unreachable,
  but the BG fixture asserts the child trace contains real specialist
  records (not self-test output) as the tripwire.
- Reference: PRD §10 (cron/background invocation path); F3.4 sink as
  the polling surface; `subprocess.Popen` (already imported in
  dispatch.py per F1.5).
