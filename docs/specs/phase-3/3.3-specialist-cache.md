# Feature 3.3: Cache layer (in-session + named namespaces)

**Phase:** 3 — Advanced
**Status:** in_progress (spec author running)
**Estimated effort:** one-day wall
**Depends on:** nothing (independent surface; builds in listed order after 3.2)
**Blocks:** nothing

## Goal

PRD R12: re-running a task reuses prior specialist outputs when the
cache key matches. A stdlib-only `scripts/specialist_cache.py` stores
specialist outputs keyed by content hash under `.cache/orchestrator/
<namespace>/` (already gitignored) with a TTL (default 24h); the
dispatcher gains `--cache-namespace` / `--cache-ttl-hours`, skips the
stub run on a hit, and stamps `cached: true` on the trace record.
Empty namespace (default) = cache fully disabled: zero behavior change
for existing users.

## Scope

Include:
- **`scripts/specialist_cache.py`** (new, stdlib-only: `argparse`,
  `hashlib`, `json`, `os`, `pathlib`, `re`, `sys`, `typing`):
  - `cache_key(role, goal, context, model, output_schema) -> str`:
    sha256 hex of `json.dumps(canonical, sort_keys=True)` where
    canonical = the 5-field dict (D45). `default=str` fallback for
    non-serializable schema values.
  - `lookup(namespace, key, ttl_hours, base=...) -> Optional[bytes]`:
    miss (None) on absent / expired / corrupt / unreadable — NEVER
    raises on cache problems (D47).
  - `store(namespace, key, payload: bytes, base=...) -> bool`: makedirs
    + write; False (never raise) on IO failure (D47).
  - Namespace rule `^[A-Za-z0-9][A-Za-z0-9_-]*$`, max 64 chars;
    violators raise `ValueError` from a `check_namespace()` helper
    (dispatcher maps to exit 2).
  - TTL: age from file mtime; expired iff age > ttl*3600.
    `ttl_hours <= 0` = never expire (D47).
  - Default base `.cache/orchestrator` relative to cwd (repo root at
    runtime); `base` param exists for tests.
  - `--self-test` only (library otherwise): 5 fixtures printing
    `SELF_TEST: 5/5 passed`: roundtrip; namespace isolation; expiry
    via `os.utime` backdate; corrupt file → miss no crash; key
    stability + sensitivity (same inputs same key, changed context
    different key).
- **`scripts/dispatch.py`**:
  - Flags `--cache-namespace NAME` (default `''` = disabled) and
    `--cache-ttl-hours H` (type=float, default 24.0). Invalid namespace
    → `error:` + exit 2 (usage, F1.5 contract).
  - Thread `cache_namespace: str = ''`, `cache_ttl_hours: float = 24.0`
    kwargs: `dispatch_plan` → `_harvest_with_retries` →
    `_run_attempts_for_spec` → `_run_one` (same threading shape as
    F2.6 `tokens_per_char`).
  - In `_run_one`, BEFORE the subprocess: if namespace set and NOT
    force-fail, `lookup()`; on hit write bytes to the seq output_path
    and return `ok` record with `cached: True` (no subprocess spawned).
    AFTER a successful non-forced run: `store()` the output bytes
    (best-effort, ignore False).
  - force-fail (`simulate`/`retry_test_overrides`) bypasses BOTH lookup
    and store (a simulated failure must actually fail; failures are
    never cached).
  - Failed runs are never stored. `--dry-run` never touches the cache.
  - Post-dispatch F2.4 schema check + F2.6 token stamp apply to cached
    records unchanged (a cached output is validated like a fresh one).
  - `--self-test` +2 fixtures (15→17): HIT (pre-populate via
    `cache_key`, dispatch, assert final record `cached is True` and
    output content == planted marker) and MISS (fresh namespace,
    assert no `cached` flag and cache file created for the key).
- **`references/cache.md`** (new, short): key recipe, flags, TTL rule,
  `cached: true` stamp, disabled-by-default, `.cache/` ignored.
- **`scripts/run_tests.py`**: dispatch 15→17, append
  `("specialist_cache.py", 5)` LAST (D19). EXPECTED_TOTAL 44→51 via
  existing `sum()`.
- `SKILL.md` §8: ONE appended bullet for `references/cache.md`.
- `README.md` status table only: F3.2 → Done, add F3.3 In progress.

## Locked behavior

- Decision D45 (controller-locked): key = sha256 over canonical
  `{role, goal, context, model, output_schema}`. Rationale: any input
  change (incl. schema) must bust the cache, else a cached output
  could fail the F2.4 check it once passed... actually it would PASS
  the same check; the risk is the reverse: same content, stricter
  schema → stale pass. Including the schema is the safe direction.
- Decision D46: layout `.cache/orchestrator/<namespace>/<key>.json`
  (already gitignored). Empty namespace disables all cache paths —
  `_run_one` must not import or touch the cache module when disabled
  (lazy import inside the enabled branch keeps the disabled path
  byte-identical in behavior).
- Decision D47: cache NEVER breaks a run. lookup misses on any
  problem; store returns False on IO failure; dispatcher ignores
  False. ttl<=0 = immortal entries.
- Decision D48: hits are stamped `cached: True` on the FINAL trace
  record and still pass through schema-check + token-estimate.
  Retried attempts: each attempt looks up independently (a miss-then-
  fail never stores; the retry re-runs).
- Gotcha: `_run_one` computes the seq output_path BEFORE the
  subprocess — the hit path writes cached bytes to that same path so
  downstream readers (schema check, token stamp, log writer) work
  unchanged.
- Gotcha: `cache_key` must be importable by the self-test to
  pre-populate: `sys.path` insert of scripts_dir (F2.4 precedent in
  dispatch.py; reverse direction here — dispatch_test imports cache).
  Keep `specialist_cache.py` import-clean (no side effects on import).
- Gotcha: planting a hit fixture requires byte content that the stub
  would NOT produce (else the fixture can't distinguish hit from run).
  Plant `{"_cache_probe": "HIT-<sid>", ...}` merged over a stub-shaped
  body — but F2.4 schema check runs on it: fixture plans must use
  `output_schema: {"type": "object"}` so the planted body passes.
- Reference: PRD R12 (24h reuse); .gitignore `.cache/orchestrator/`;
  F2.6 kwarg-threading precedent.
