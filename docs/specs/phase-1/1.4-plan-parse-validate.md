# Feature 1.4: Plan parsing + validation

**Phase:** 1 — MVP, fixed models

**Depends on:** 1.2, 1.3

## Goal

A stdlib-only CLI validator that parses an Orchestrator plan JSON file and
rejects invalid plans with actionable errors — before any `delegate_task` is issued.

## Scope

Include:
- `scripts/validate_plan.py` (STDLIB ONLY: `json`, `sys`, `argparse`, `typing` —
  D7 locked; no third-party imports even though `jsonschema` happens to exist on
  this host. Skill scripts must run on any Hermes host with zero installs).
- CLI contract: `python3 scripts/validate_plan.py PLAN.json [--quiet]` plus a
  `--self-test` flag. Exit 0 = dispatchable, 1 = invalid plan, 2 = usage/file error.
- Error rules (each a distinct `ERROR:` line, exit 1):
  - E1 shape: `task_summary` non-empty str; `specialists` list; `batches` list;
    `dependencies` dict. Missing/wrong-type → error. Unknown top-level keys →
    `WARNING:` (forward-compat), never error.
  - E2 count: 3–15 specialists, else error.
  - E3 per-specialist: all 7 fields present (`id`, `role`, `goal`, `context`,
    `output_schema`, `tools`, `model`); `id` unique non-empty str; `goal` /
    `context` non-empty; `output_schema` must be a JSON object (dict) — content
    unchecked (F1.6 scope); `tools` non-empty list of str; `model` non-empty str.
  - E4 role-known: role outside the catalog (13 core + 4 fixed optional +
    `domain-expert-*` pattern) → `WARNING:`, not error — synthesized roles are
    allowed. Catalog list HARDCODED as a frozenset with a comment pointing at
    `references/archetypes.md` as the human source (D8: hardcode, don't
    markdown-parse prose — brittle; update the frozenset when the catalog changes).
  - E5 batches: list of non-empty int lists; every index in range; every
    specialist index covered EXACTLY once (missing → error, duplicate → error).
  - E6 dependencies: keys and values must be existing ids; no self-dependency;
    no cycles (error names the cycle); ordering consistent with batches
    (dependent's batch position strictly after each prerequisite's — else error).
  - E7 reviewer rule: ≥1 role matching `reviewer-*` or `== critic`, else error.
  - E8 nesting guard: no nested `specialists` key below top level (defensive
    depth check), else error.
- Warnings (prefixed `WARNING:`, exit stays 0 with no errors): unknown top-level
  keys, unknown roles, specialist `model` != Phase-1 default (forward-compat note).
- Output: exit 0 prints `PLAN_VALID: N specialists in B batches` (+ warnings);
  exit 1 prints `PLAN_INVALID: N error(s)` + `ERROR: <path>: <message>` lines;
  exit 2 prints an actionable message for missing file / malformed JSON / bad usage.
- `--self-test`: built-in fixtures exercising every E-rule (valid plan; count<3;
  duplicate id; out-of-range batch index; batch missing a specialist; duplicate
  coverage; unknown dep id; self-dep; cycle; batch-order violation; missing
  reviewer; non-object output_schema; nested specialists) asserting expected
  pass/fail through the same `validate()` function the CLI uses. All asserts pass
  or the flag exits non-zero.
- SKILL.md §4 Validate paragraph: ONE appended pointer clause —
  `Validate with scripts/validate_plan.py (exit 0 = dispatchable).`
- `README.md` status table: F1.4 → In progress.

Exclude (for now):
- `output_schema` CONTENT validation (F1.6). Dispatching (F1.5). pytest suite
  (F1.10 — stdlib `unittest` vs pip `pytest` decided there; host has neither
  today). No new dependencies, no new dirs.

## Spec section

Minimal valid fixture (must exit 0 — controller reuses this exact shape):

```json
{"task_summary": "smoke",
 "specialists": [
  {"id": "r1", "role": "researcher", "goal": "gather X", "context": "task slice",
   "output_schema": {"type": "object"}, "tools": ["file"],
   "model": "opencode-go/deepseek-v4.1-flash"},
  {"id": "cr", "role": "critic", "goal": "stress-test", "context": "draft",
   "output_schema": {"type": "object"}, "tools": ["file"],
   "model": "opencode-go/deepseek-v4.1-flash"},
  {"id": "wr", "role": "writer", "goal": "write it", "context": "outputs",
   "output_schema": {"type": "object"}, "tools": ["file"],
   "model": "opencode-go/deepseek-v4.1-flash"}],
 "batches": [[0], [1], [2]],
 "dependencies": {"wr": ["r1"]}}
```

`validate()` returns `(errors: list[str], warnings: list[str])`; `main()` maps to
exit codes. Keep functions pure and importable (F1.10 will import them).

## Implementation notes

- Decision D7 (controller-locked): stdlib-only — this host has no pytest and
  skill scripts must run anywhere with zero installs. `typing` allowed (stdlib).
- Decision D8: hardcoded role frozenset + source comment, not markdown parsing.
- Gotcha: E5 covers EXACTLY once — missing AND duplicate are both errors.
- Gotcha: E6 batch-order uses batch POSITION (index into `batches`), not
  specialist index. Cycle check: iterative DFS, ≤15 nodes.
- Gotcha: `--quiet` suppresses `PLAN_VALID` chatter but never errors/warnings;
  exit codes are the contract, not the text.
- Reference: `references/orchestrator.md` §§2–4 (schema, index-vs-id, rules),
  `references/archetypes.md` §§1–3 (role list, shape).
