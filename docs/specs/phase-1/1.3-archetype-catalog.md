# Feature 1.3: Static archetype catalog

**Phase:** 1 — MVP, fixed models
**Status:** completed
**Estimated effort:** half-day wall (subagent implement + two-stage review)
**Depends on:** 1.1
**Blocks:** 1.4

## Goal

The static specialist catalog from PRD Appendix A as `references/archetypes.md` —
every core + optional archetype with purpose and default tools, plus the
archetype-shape contract the Orchestrator uses to synthesize task-specific roles.

## Scope

Include:
- `references/archetypes.md` with: all 13 core roles (planner, researcher,
  comparator, coder-impl, coder-test, reviewer-spec, reviewer-quality, critic,
  risk-analyst, writer, formatter-doc, pr-drafter, data-extractor), each with
  Purpose + Default tools transcribed from PRD Appendix A; all 5 optional roles
  (domain-expert-`<field>`, citation-checker, blocker-detector, bench-runner,
  summarizer) with one-line purpose each; the archetype-shape contract (the 7
  specialist fields + plan must-include `batches` + `dependencies`, pointing back
  to `references/orchestrator.md` §2 for the normative schema); an explicit
  statement that the Orchestrator may synthesize task-specific roles by following
  the shape (it is not limited to this list).
- `README.md` status table: F1.3 → In progress (F1.1 row pattern).

Exclude (for now):
- Per-archetype output schemas (F1.6). Validator code (F1.4). No Python/scripts.
- Do NOT touch SKILL.md — §8 already points at `references/archetypes.md`.
  Verify the pointer exists; leave the file byte-identical.

## Spec section

Source of truth is PRD Appendix A — transcribe, don't reinvent. Tool defaults
verbatim from the PRD table:

| Archetype | Default tools |
| --------- | ------------- |
| planner | file, terminal (read) |
| researcher | web_search, web_extract, file, terminal (read) |
| comparator | file, terminal (read) |
| coder-impl | file, terminal |
| coder-test | file, terminal |
| reviewer-spec | file, terminal |
| reviewer-quality | file, terminal |
| critic | file |
| risk-analyst | file, terminal (read) |
| writer | file |
| formatter-doc | file, terminal |
| pr-drafter | terminal, github |
| data-extractor | file, terminal, integrations |

Shape contract (must appear in the file): every chosen archetype gets `id`
(unique within the plan), `role`, `goal` (one sentence + success criterion),
`context` (task slice, upstream outputs, role instructions — never the full
conversation), `output_schema` (content defined in F1.6), `tools` (least
privilege subset), `model` (default `opencode-go/deepseek-v4.1-flash`). The plan
additionally carries `batches` (`number[][]`, indices) and `dependencies`
(`Record<id, id[]>`).
