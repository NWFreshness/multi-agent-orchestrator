## Spec section

Plan JSON shape the Orchestrator must return (field names locked):

```json
{
  "task_summary": "short-slug",
  "specialists": [
    {"id": "r1", "role": "researcher", "goal": "one sentence + success criterion",
     "context": "task-relevant background and inputs",
     "output_schema": "{...json schema...}",
     "tools": ["file", "terminal"],
     "model": "opencode-go/deepseek-v4.1-flash"}
  ],
  "batches": [[0, 1], [2]],
  "dependencies": {"2": ["r1"]}
}
```

Locked semantics:
- `batches` are **index arrays** into `specialists[]` (PRD `number[][]`); each
  inner array is dispatched as ONE `delegate_task` call. `dependencies` maps
  specialist id → prerequisite ids for the synthesizer's ordering.
- Specialist `model` defaults to `opencode-go/deepseek-v4.1-flash` in Phase 1.
- Plan rules: 3–15 specialists (target ~10); at least one `reviewer-*` or `critic`
  role; dependency edges required wherever ordering matters; nesting depth ≤ 2.
  Invalid plans are rejected with a clear error, never dispatched.
- Short-circuit (R15) is decided by the PARENT before spawn; small tasks never
  reach the Orchestrator and are logged as `short_circuit`.
