# Feature 1.9: `/orchestrate` slash command registration

**Phase:** 1 — MVP, fixed models
**Status:** in_progress
**Estimated effort:** half-day wall (subagent implement + two-stage review)
**Depends on:** 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8
**Blocks:** 1.10

## Goal

Register `/orchestrate <task>` as a Hermes slash command so a user in any
Hermes session can type the command, pass a task, and have the controller
session dispatch the full orchestration loop (short-circuit → spawn
Orchestrator → plan → validate → batch dispatch → recover → synthesize →
log). The command is the single user-facing surface of the skill.

## Scope

Include:
- A Hermes slash command named `orchestrate` (no leading slash in the
  registration, but invoked as `/orchestrate` per Hermes convention).
  - Signature: `orchestrate <task>` (one positional arg: the task string).
  - Arg validation: task must be non-empty; empty/missing → error message.
  - Help text (in `--help` / `/help orchestrate`): one-line description that
    matches the SKILL.md frontmatter description's extendable tail, plus
    a usage line.
- The handler does NOT actually run the full orchestration loop in v0.1.
  Phase 1 ships the *registration* (so the command exists, has help, parses
  args, and the user sees a clear "starting orchestration…" message). The
  full loop is a Phase 2+ concern (a real LLM call isn't wired up in Phase 1
  — see the F1.5 stub design).
- The handler echoes a clear startup message that names the skill + PRD
  phase ("Multi-Agent Orchestrator (Phase 1 stub): would plan <task>. Full
  loop ships in Phase 2." or similar) — confirm exact wording with the
  reviewer, but the principle is the user must see a deterministic response.
- Per the `hermes-agent` skill's "Adding a Slash Command" recipe (3 files):
  1. `hermes_cli/commands.py` — add `CommandDef` to `COMMAND_REGISTRY`.
  2. `cli.py` — add handler in `process_command()`.
  3. (Optional) `gateway/run.py` — add gateway handler for Telegram/Slack
     mirroring. Required for full functionality across platforms, but
     optional for v0.1 (the CLI path is the primary surface).
- A `hermes skills inspect multi-agent-orchestrator` run after registration
  must show the slash command in the skill's command list. (If the inspector
  doesn't surface commands, fall back to `hermes --help | grep orchestrate`.)
- SKILL.md frontmatter may need ONE additional optional field
  (`metadata.hermes.slash_command: orchestrate`) — only if Hermes's current
  convention requires it for the command to be discoverable. Check by
  reading the `hermes-agent` skill; add only if the convention demands.
- `README.md` status table: F1.9 → In progress.
- `docs/specs/phase-1/1.9-slash-command.md` Status → completed.

Exclude (for now):
- Wiring the handler to actually spawn the Orchestrator and run the full
  loop. Phase 1 = registration only. The handler says "would plan" and
  returns. This is the same boundary as F1.5's stub.
- Telegram / Slack / WhatsApp platform wiring (Phase 3 PRD F3.4).
- New tests; the existing F1.10 plan covers tests.

    name="orchestrate",
    summary="Multi-Agent Orchestrator (Phase 1 stub)",
    usage="orchestrate <task>",
    handler=_handle_orchestrate,
    args={"task": "the user task to orchestrate"},

non-empty task string, else `error: orchestrate: task is required (usage:
orchestrate <task>)`.

## Implementation notes

- Decision D17 (controller-locked): the handler is a STUB in v0.1. The full
  loop (Orchestrator spawn + plan + validate + dispatch + recover +
  synthesize + log) wires up in Phase 2+ once a real LLM call replaces
  the F1.5 stub. Trying to wire the loop in 1.9 would conflate two phases.
- Decision D18: the handler does NOT touch `~/.hermes/profiles/builder/` or
  any per-profile config. The registration lives in the global
  `commands.py`. Profile-level skills are loaded per-profile but the slash
  command is global.
- Gotcha: the `hermes-agent` skill is a guide, not a literal. The implementer
  should READ `~/.hermes/hermes-agent/hermes_cli/commands.py` to learn the
  real `CommandDef` shape (current version may differ from the skill text).
  Grep for `CommandDef` and `COMMAND_REGISTRY` to find the real registration
  point.
- Gotcha: the `hermes-agent` skill is in the user's skill tree
  (`~/.hermes/profiles/builder/skills/autonomous-ai-agents/hermes-agent/`).
  Load it before making changes to the local checkout so the implementer
  has the latest command-registration conventions.
- Reference: `hermes-agent` skill §"Adding a Slash Command" (3 files).
  PRD R1 (invocation paths — slash + programmatic + skill call).
